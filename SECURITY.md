# Політика безпеки

Дякуємо, що допомагаєте зробити проєкт безпечнішим.

## Як повідомити про вразливість

**Не створюйте публічний Issue** для опису вразливості.

Будь ласка, використайте один із каналів:

1. **GitHub Security Advisories** — відкрийте вкладку **Security → Advisories → Report a vulnerability** у цьому репозиторії та опишіть проблему приватно.
2. Альтернатива — приватне повідомлення мейнтейнерам через профілі GitHub (якщо Advisory недоступний за політикою організації).

У звіті бажано вказати:

- тип проблеми та потенційний вплив;
- кроки відтворення або умови експлуатації;
- запропоноване виправлення (за наявності).

## SLA відповіді

Ми прагнемо підтвердити отримання звіту протягом **7 робочих днів** та узгодити подальші дії (перевірка, патч, координація релізу).

Точні строки можуть залежати від складності й доступності команди.

## Після виправлення

За узгодженням ми можемо опубліковувати advisory або changelog entry із посиланням на виправлення.

## Що зазвичай не вважається вразливістю

Приклади (можуть переглядатися індивідуально):

- відсутність HTTP security headers без чіткого доказу впливу на користувачів цього сервісу;
- проблеми лише в застарілих версіях браузера або середовища без підтримки з нашого боку;
- самохостинг без ізоляції та конфігурація за замовчуванням без опису реального сценарію атаки на очікуваний деплой.

Якщо сумніваєтеся — безпечніше надіслати звіт; ми відповімо та класифікуємо звіт.
