# ADR 0001: Використання Prisma як ORM

## Status

Accepted

## Context

Потрібен типобезпечний доступ до **PostgreSQL**, керовані **міграції** та узгодженість між схемою БД і TypeScript-кодом. Команда обмежена в часі (один місяць), тому важливі швидкість розробки та передбачуваність деплою.

## Decision

Обрати **Prisma** як основний ORM і джерело міграцій (`prisma migrate`).

## Consequences

**Плюси:**

- Автогенерація типів для запитів і моделей.
- Декларативна `schema.prisma`, зрозуміла для всієї команди.
- Транзакції через `prisma.$transaction` узгоджуються з фінансовими операціями.

**Мінуси:**

- Зміни схеми потребують дисципліни при паралельній роботі (merge конфлікти).
- Складні сирі SQL мігрують рідше — потрібні `queryRaw` лише за потреби.

## Alternatives considered

- **TypeORM / Sequelize** — менш консистентний DX для типів і міграцій у порівнянні з Prisma для нашого кейсу.
- **Kysely + чисті SQL міграції** — більше контролю, але вищий поріг входу для команди за місяць.
