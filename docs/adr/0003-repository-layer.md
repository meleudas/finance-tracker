# ADR 0003: Окремий рівень репозиторіїв над Prisma

## Status

Accepted

## Context

Бізнес-логіка в сервісах напряму змішана з викликами Prisma ускладнює **unit-тести** і приховує складні запити в різних місцях. Потрібна чітка межа між **правилами домену** та **доступом до даних**.

## Decision

Ввести каталог **`src/repositories/`**: тонкі модулі, що інкапсулюють **Prisma** (запити, оновлення, робота з `tx` у межах `prisma.$transaction`, ініційованої сервісом).

- **Services** — бізнес-логіка та orchestration; **не** імпортують `PrismaClient` напряму.
- **Repositories** — без бізнес-правил; фільтрація за `userId` як частина **контракту доступу до даних**, не як доменне рішення «чи дозволено операцію» (перевірка прав/інваріантів залишається в сервісі).

## Consequences

**Плюси:**

- Простіші тести сервісів через мок репозиторіїв.
- Один місце для складних запитів і індексованих `where`.

**Мінуси:**

- Додатковий шар файлів і узгодження сигнатур сервіс ↔ репозиторій.

## Alternatives considered

- **Лише сервіси + Prisma** — менше файлів, але гірша ізоляція тестів і сильніше зв’язування з ORM.
- **Active Record стиль через розширені Prisma-моделі** — не відповідає обраній шаруватій структурі Express-проєкту.
