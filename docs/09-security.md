# Безпека

**Пов’язано:** [04-tech-stack.md](04-tech-stack.md) · [08-api-design.md](08-api-design.md) · [11-logging.md](11-logging.md)

Мета — зменшити поверхню атаки для публічного REST API та захистити облікові дані й фінансові записи.

## Заголовки HTTP (Helmet)

- Увімкнути **Helmet** за замовчуванням.
- **CSP** (Content-Security-Policy): для API це здебільшого захист від неочікуваних сценаріїв і звуження XSS-наслідків при помилковій віддачі HTML; налаштування під Swagger UI (inline scripts) — явно дозволити потрібні джерела тільки для маршруту документації.

## CORS

- **Allowlist** origins через конфіг (не `*` у production).
- Якщо використовуються **cookies** з `credentials`, налаштувати `origin` + `credentials: true` узгоджено на клієнті та сервері.

## Rate limiting

- Глобальний м’який ліміт + жорсткий на **`/api/v1/auth/*`** (login, refresh) для протидії bruteforce.
- Відповідь **429** з `Retry-After` за можливості.

## Автентифікація та сесії (JWT)

Рекомендована схема для MVP:

| Токен | TTL | Зберігання |
|-------|-----|------------|
| Access JWT | короткий (наприклад 15 хв) | `Authorization` header або memory на клієнті |
| Refresh JWT | довший (наприклад 7 д) | **httpOnly**, **Secure**, **SameSite** cookie |

**Практики:**

- Алгоритм підпису **HS256/RS256** — обрати один; ключі лише з env.
- Перевірка `exp`, `iss`, `aud` за потреби.
- Оновлення access через окремий ендпоінт з ротацією refresh (опційно sliding sessions — після MVP).

## Паролі (bcrypt)

- Хешування через **bcrypt**, cost factor **12** (або вище якщо інфра дозволяє).
- Ніякого plaintext у логах і відповідях; у валідації — мінімальна довжина і складність пароля (правило в Zod).

## Валідація та санітизація вводу

- Усі входи проходять **Zod**.
- Додаткова **sanitization** для рядків, що можуть потрапити в запити/логи (залежно від обраної бібліотеки).
- Заборонено складати SQL вручну; лише **Prisma query API**.

## Авторизація (доступ до даних)

- Кожен запит до ресурсу має містити перевірку **власності** (`where: { id, userId }`).
- Не покладатися лише на `id` з URL без перев’язки з поточним користувачем.

## Секрети та конфігурація

- Секрети тільки через **змінні середовища** (див. `src/config/`).
- У production: секрети з секрет-менеджера або CI secrets, не в image.

## OWASP — орієнтир (короткий чеклист)

- [ ] Injection: Prisma + параметризовані запити
- [ ] Broken auth: rate limit, bcrypt, TTL токенів
- [ ] Sensitive data: HTTPS, httpOnly cookies, мінімізація PII у логах
- [ ] Security misconfiguration: Helmet, суворий CORS, вимкнути зайві ендпоінти в prod
- [ ] Logging: без секретів, маскування полів (див. [11-logging.md](11-logging.md))
