# Огляд проєкту

**Батьківський документ:** [README.md](../README.md) — вхідна точка.

## Мета

Побудувати **REST API** для трекера особистих фінансів: реєстрація/автентифікація користувачів, рух грошей між рахунками через транзакції, категоризація, бюджети та звіти. Фокус — **надійність даних**, **безпека**, **перевірюваність** і **зрозумілі контракти** для клієнтів (web/mobile).

## Скоуп (MVP за місяць)

| Область | Включено |
|---------|----------|
| Користувачі | Реєстрація, логін, сесія (JWT + httpOnly cookies) |
| Рахунки | CRUD, валюта, баланс (пообчислений/кешований залежно від рішення) |
| Категорії | Дохід/витрата, ієрархія (опційно) |
| Транзакції | CRUD, фільтри, пагінація, прив’язка до рахунку та категорії |
| Бюджети | План на період (місяць) за категорією |
| Звіти | Агрегати за період, порівняння з бюджетом |
| API | Версія `/api/v1`, OpenAPI (Swagger) з Zod |
| Інфра | Docker, CI/CD, структуровані логи, централізовані помилки |

**Поза скоупом MVP** (можна винести в backlog): багатовалютна конвертація в реальному часі, банківський імпорт (PSD2), спільні сімейні бюджети, webhooks, push-нотифікації.

## Користувачі та сценарії

1. Користувач реєструється, створює один або кілька рахунків (готівка, карта).
2. Додає транзакції доходу/витрати з категорією.
3. Ставить місячний бюджет по категорії.
4. Переглядає звіт за період і відхилення від бюджету.

## Нефункціональні вимоги

- **Час відповіді:** типові запити < 200 ms на локалі / staging при помірному навантаженні.
- **Цілісність:** фінансові операції узгоджені з БД (**транзакції БД** на рівні **сервісу**, читання/запис через **репозиторії**).
- **Безпека:** OWASP-орієнтовані практики (див. [09-security.md](09-security.md)).
- **Спостережуваність:** логи з correlation ID, без витоку секретів (див. [11-logging.md](11-logging.md)).
- **Тестування:** coverage ≥ 80% на критичних модулях (сервіси, репозиторії, auth) (див. [12-testing.md](12-testing.md)).

## Метрики успіху (кінець місяця)

- Усі ендпоінти MVP задокументовані в OpenAPI.
- CI: lint, typecheck, test, build — зелені на `main` / `dev`.
- Міграції Prisma застосовні з нуля (`migrate deploy`) + seed для демо-даних.
- Команда з 3 розробників може паралельно працювати без систематичних merge-конфліктів у `schema.prisma` (домовленості в [06-team-workflow.md](06-team-workflow.md)).

## Обмеження та припущення

- Один власник даних — один `User` (без shared accounts у MVP).
- Клієнтський UI не входить у репозиторій; API — джерело істини.
- Розгортання: контейнер + PostgreSQL; деталі в [14-setup.md](14-setup.md).
